# Domain docs

Use a single context for Esdieff: `GLOSSARY.md` at the repository root and architecture decision records in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being explored.

Add or update terms when a change needs new domain language. Record a design
decision when its rationale and consequences will help future contributors.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues, code, tests and
proposals. If a needed concept is missing, reconsider the name or explain the
proposed term alongside the change.

## ADR conflicts

Surface any conflict with an existing ADR explicitly, naming the ADR and explaining why the decision may need to be revisited. Follow the maintainer's decision process before changing a settled design.
