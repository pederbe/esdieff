# 0047: Context reuse with existing composition

[Context draft 06, Section 4.2](https://www.ietf.org/archive/id/draft-ietf-asdf-sdf-nonaffordance-06.txt) permits Context definitions to reuse data descriptions through `sdfRef` and directs reusable cross-model descriptions into `sdfData`. Context checking and inspection now support same-document and supplied-Catalogue composition. This supersedes the provisional reference-reuse limitation in [ADR 0046: Inline Context draft support](0046-inline-context-draft-support.md) for consumers inside Context. Its absent-nullability and undefined-requiredness policies continue to apply to final effective descriptions.

Objects and Things retain their Context groups when reused. References use the existing resolver, JSON Merge Patch, scoped failures, nearest content origins and importing consumers under [ADR 0006: Scoped reference failures](0006-scoped-reference-failures.md), [ADR 0020: Owned effective views and nearest origins](0020-owned-effective-views-and-nearest-origins.md), [ADR 0023: Supplied global composition and dependency scope](0023-supplied-global-composition-and-dependency-scope.md) and [ADR 0036: Copied reference relocation](0036-copied-reference-relocation.md). There is no Context-specific reference identity or retrieval mechanism.

A Context consumer can reference another Context or its nested data descriptions, including through a composed target path. Its final role keeps absent nullability unavailable even when the source is an ordinary `sdfData` description. Explicit inherited nullability remains meaningful, and deleting it restores the Context uncertainty. The consuming Context gains no Property characteristics and does not become a mandatory affordance.

Reusing a Context description in a non-Context role remains a scoped unavailable capability. Otherwise an absent default withheld by Context could silently become the base-SDF default. Authors sharing descriptions across roles or models should factor them into `sdfData`. Supporting that export would require a separate policy for the transferred defaults. Keeping the limitation there allows useful Context composition without resolving the draft's default conflict.
